# Threat model (Phase 10)

A short, honest model of what DataCanvas protects, from whom, and where it stops. Review it whenever a feature adds a route, a file, or a network call.

## Assets (what we protect)

| Asset                                    | Why it matters                                                                                                   |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Database credentials                     | Give access to the user's data.                                                                                  |
| Schema metadata                          | Table and column names reveal how a system works.                                                                |
| Open database connections                | Whoever can call the API can use them (read metadata, and rows where data viewing is on).                        |
| Table contents (when data viewing is on) | The most sensitive asset: whoever can call the API with the token can read rows of tables on an open connection. |
| Saved files (`~/.datacanvas`)            | Connection details (no password) and layouts.                                                                    |
| The database itself (when writes are on) | Whoever can call the write routes on an unlocked connection can change or destroy rows and structure.            |

## Attackers and what they can try

### 1. A malicious website open in the user's browser

| Attempt                                                   | Control                                                                                                                                                                                                                                                                                                            | Residual                                                                                      |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| `fetch("http://127.0.0.1:4747/api/...")` to read metadata | No CORS headers: the browser hides the response. `Sec-Fetch-Site: cross-site` is refused. Cookie is `SameSite=Strict`. Token required.                                                                                                                                                                             | None known.                                                                                   |
| Forged form or fetch that changes state (connect, delete) | Origin check; JSON-only bodies (a plain HTML form cannot send them); token.                                                                                                                                                                                                                                        | None known.                                                                                   |
| DNS rebinding: attacker domain resolves to 127.0.0.1      | Host check accepts only `127.0.0.1:<port>` and `localhost:<port>`.                                                                                                                                                                                                                                                 | None known.                                                                                   |
| Embedding the app in a frame (clickjacking)               | `frame-ancestors 'none'` and `X-Frame-Options: DENY`.                                                                                                                                                                                                                                                              | None known.                                                                                   |
| Calling the rows endpoint, or switching data viewing on   | Everything above (Host, Origin, `Sec-Fetch-Site`, token, no CORS), checked in the front door and again in the route. The per-connection opt-in is off by default and is read before anything about the table is looked up, so a refused connection answers the same for a table that exists and one that does not. | Anyone holding the token can switch data viewing on: the same trust as before, higher stakes. |
| Guessing the token                                        | 256-bit random value, constant-time comparison.                                                                                                                                                                                                                                                                    | None practical.                                                                               |

### 1b. Rows leaving by a side door

| Attempt                                               | Control                                                                                                                                                                                                                                                                                                                                                                                                                              | Residual                                                                           |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| Rows in logs                                          | Only error codes are logged, never bodies, cursors or rows. A rule fails the build if the data viewer uses `console`.                                                                                                                                                                                                                                                                                                                | None known.                                                                        |
| Rows in error messages                                | Raw database messages are never returned (they can contain values). A forged paging position, a sort or a condition the table does not allow, and a value that does not fit a column's type all get a fixed message that repeats no name and no value.                                                                                                                                                                               | None known.                                                                        |
| Rows saved to disk                                    | Not in workspaces, snapshots, `run.json` or profiles. A rule fails if the data viewer or the stores touch `localStorage`, `sessionStorage`, `indexedDB`, cookies or caches, and a browser test checks the browser storage after rows were read.                                                                                                                                                                                      | The browser's own memory, and the operating system's swap.                         |
| Rows cached                                           | `Cache-Control: no-store`. Reads are `POST`, so a table name and a paging position are never in a URL, the history or a log.                                                                                                                                                                                                                                                                                                         | Browser extensions with access to the page.                                        |
| A secret shown by accident                            | Columns whose names look sensitive are not selected at all; the server never sends them unless the person reveals that column for the current view. A browser test checks the value is nowhere in the page.                                                                                                                                                                                                                          | Names are only a hint: a column called `notes` can hold a password.                |
| Shoulder surfing or screen sharing                    | A **Blur values** switch, held in memory only.                                                                                                                                                                                                                                                                                                                                                                                       | It is for that purpose only: it does not change what is read, copied or announced. |
| A query that hurts the database                       | Read-only transaction, statement timeout, row, column, cell and response caps, one read at a time (three waiting, then `429`), keyset paging, capped `OFFSET` for tables without a key.                                                                                                                                                                                                                                              | A slow view or a heavy table still costs the database up to the timeout.           |
| SQL injection through names, cursors or values        | The statement has one shape. Names come from the catalog and are quoted; the page size, the cell limit and the cursor are bound parameters. Tested on a fixture of awkward names.                                                                                                                                                                                                                                                    | None known.                                                                        |
| Reading a hidden column through a condition or a sort | A hidden column is refused for every operator (even the null tests) and for sorting until the person reveals it, because "starts with a", "starts with b" would read it back one letter at a time. The adapter refuses it (tested against a real PostgreSQL), the server passes the request through unchanged, and the browser does not offer it; when a column is hidden again its filters and sort go with it.                     | Names are only a hint, as before.                                                  |
| SQL injection through a sort or a condition           | The request is strict at every level; the operator is an enum, chosen from a fixed table by its own keys; column names come from the catalog and are quoted; every value is a bound parameter; `contains` and `starts with` avoid `LIKE`, so there are no wildcards. A generated test of 400 hostile requests checks the statement's grammar, and rule tests fail on `LIKE`, on a loosened schema, or on text built from either key. | None known.                                                                        |
| A heavy sort or condition loads the database          | The statement timeout for these reads is 5 seconds (measured: indexed reads take about 1 ms, an unindexed sort of 5 million rows about 230 ms, `contains` on wide text the longest), one read runs at a time per connection, and a stopped read is answered with a fixed sentence.                                                                                                                                                   | Each try can cost up to 5 seconds of work.                                         |
| The value of a condition leaks                        | It is typed into a component, held in React state, and sent only in a `POST` body; never in a URL, a log, an error message, a file or the browser's storage (a browser test checks the storage).                                                                                                                                                                                                                                     | The browser's own memory.                                                          |
| Rows hidden by row-level security                     | The page says whether security applies to the connected role, and the Data section shows a note when it does.                                                                                                                                                                                                                                                                                                                        | The check judges role membership approximately, so the wording says "may".         |

### 2. A web app on another port of 127.0.0.1

Cookies are shared across ports, so it receives the cookie when the browser visits it. From a browser it still cannot call our API (Origin / `Sec-Fetch-Site` checks, no CORS). **Residual:** its _server side_ could replay the cookie; that is a hostile local program (next).

### 3. Another program on the machine

- Other users: the server listens on loopback and requires the token; a different user cannot normally see the token. **Residual:** a hostile administrator.
- While DataCanvas runs, the token is also in `~/.datacanvas/run.json` (mode 0600) so a second launch can reopen the running instance. It is deleted on clean shutdown; a stale file is useless because the token dies with the process.
- Same user: can read the process environment and the CLI output, and can read `~/.datacanvas`. **Out of scope:** this attacker already controls the account. We still keep the password out of every file, so even they find no password at rest.

### 4. Someone who gets a diagram, workspace file or snapshot file

Contains table and column names, and never row data, whether or not data viewing is on (a snapshot also column types, defaults, comments, index and constraint definitions, view queries, function and trigger bodies, and row-level-security policy expressions and role names, which can describe business logic and access rules) but no row data and no connection credentials. Definitions are copied exactly as written, so they can contain secrets someone typed into them (a literal key in a function body, a password in a view's query); an exported file carries them along, and DataCanvas does not scan for them. The export dialog and the Snapshots tab say so. Imported workspace and snapshot files are validated (unknown keys refused, every list and string bounded), size-limited, and can never overwrite existing data: an imported snapshot always gets a new id.

### 5. Hostile input

Every request body and query string is validated with a schema, size-limited, and answered with fixed messages. Identifiers are validated before touching the file system (no path traversal). Search input, every paging position and every value of a condition are passed as parameters, never concatenated into SQL, and the page size, the number of columns revealed, the cursor, the sort and the number and length of conditions are bounded. There is no endpoint that runs SQL, except the one of the SQL view (1.6.0): attacker 8.

### 6. A hostile or compromised database server

Responses are treated as data. Queries are read-only and time-bound. Names and cell values are rendered as text (React escapes them), never as HTML; every value is converted to text and cut inside the database, so a huge value never travels. **Residual:** a very large schema costs memory; results are capped per request.

### 7. Changing the database (writes, 1.4.0)

New capability: **changing and destroying data and structure**. The worst case of a stolen session token was reading; with writes it is writing, but only on a local database, in a process started with `--enable-writes`, on a connection the person unlocked.

| Attempt                                          | Control                                                                                                                                                                                                                                                 | Residual                                                                                                                                                                |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A web page or local program calls a write route  | Host, Origin, `Sec-Fetch-Site` and token checks; `--enable-writes` at start-up (not reachable from the API, and an inherited environment variable is removed); local-only; per-connection unlock                                                        | Someone holding the token, on a machine where writes were enabled and a connection unlocked, can write                                                                  |
| Writing to production by mistake                 | Local-host rule; typed database name; the server's reported address in the unlock dialog; a red badge; the role warning                                                                                                                                 | A tunnel or proxy on `127.0.0.1` to a remote database looks local                                                                                                       |
| SQL injection through names or values            | Strict JSON operations with no SQL, WHERE or expression field at any level; names checked against the catalog and quoted; values bound as parameters and cast in the database; types and defaults from fixed lists                                      | None known                                                                                                                                                              |
| Applying something other than what was previewed | A single-use preview id that expires after five minutes; apply takes only the id; the statements and values stay on the server                                                                                                                          | None known                                                                                                                                                              |
| Overwriting someone else's newer change          | The update runs only if the changed columns still hold what the person saw; exactly one row or a rollback                                                                                                                                               | Two people editing different columns of one row do not conflict, which is correct                                                                                       |
| Data loss from a delete or a drop                | A delete previews the foreign keys that point at the row and their `ON DELETE` actions, and needs a tick to confirm. A drop needs the table name typed, uses no `CASCADE`, and is refused while anything depends on it. Each change is one transaction. | A foreign key's own `ON DELETE` action (for example `CASCADE`) still removes or changes rows in other tables when you delete a row; a committed change cannot be undone |
| Taking the database down with a lock             | `lock_timeout` of 3 seconds; statement timeouts of 15 seconds (rows) and 60 seconds (structure); lock and rewrite warnings; one write at a time per connection                                                                                          | A long `ALTER` that has the lock still blocks others until it finishes                                                                                                  |
| Values leak through errors, logs or history      | Database errors mapped from the SQLSTATE to fixed text; values never logged; the session history holds names only; previews never send the values back                                                                                                  | The browser's and the server's memory                                                                                                                                   |
| A role with far more rights than needed          | The role check and its warnings, in read-only mode and with writes unlocked                                                                                                                                                                             | A warning can be ignored                                                                                                                                                |
| Writes enabled by habit                          | A notice at every start with the flag; the unlock is per connection and per session and is never saved                                                                                                                                                  | A person who always starts with the flag                                                                                                                                |

### 7b. Review of the write path (1.5.2)

Before 1.5.2 the write path was read end to end by a second reviewer working only from the code, looking for injection, a bypass of the unlock or the preview, reaching writes from another origin, leaks, and resource abuse. It found no way to run SQL of its own or to apply something other than what was previewed, and no way to reach a write without the token except a development server, where there is none (fixed, below). What it did find, and what was done:

| Finding                                                                                                          | Result                                                                                                                                                             |
| ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A type change that rounds or cuts values (for example bigint to integer, numeric to integer) was a quiet preview | Fixed: such a change (numeric to integer, timestamp to date, fewer decimals) is marked destructive and carries a `lossy` warning (decision 139)                    |
| The plan guard did not notice a column whose type changed after the preview                                      | Fixed: the guard pins each named column's type, length and precision too                                                                                           |
| A delete listed only the foreign keys that point straight at the row, not a chain of `ON DELETE CASCADE`         | Fixed: the warning names the tables further down the chain, to its end                                                                                             |
| `pnpm run dev` with the writes variable set had writes on and no session token                                   | Fixed: writes need a session token as well (decision 140)                                                                                                          |
| Structure statements are sent as text, so one stray `;` in a builder would start a second statement              | Guarded by a test that no structure statement has a semicolon outside quotes; every name already comes from the catalog or the new-name check                      |
| The session token is a cookie, and cookies are shared across ports                                               | **Accepted**, as in attacker 2: a hostile local web server could replay it. A second secret held in memory by the page is the fix, and is left for a later release |
| Unlock and the typed table name are friction, not authentication                                                 | **Accepted** and now said here: anyone holding the token can type them                                                                                             |
| Many large previews, or slow user-defined casts, can hold memory or a pooled connection                          | **Accepted** for a local single-user tool: previews are capped at 20 per connection and expire after five minutes                                                  |

### 8. Text typed into the SQL view (1.6.0)

New capability: **a request that carries SQL text** (`POST /api/connections/:id/run`). Until now no text typed by the person became SQL. It is the narrowest version that is still useful: one statement, read-only, with the viewing switch, and no way to write even when writes are enabled (decision 141).

| Attempt                                                                                            | Control                                                                                                                                                                                                      | Residual                                                                                                                         |
| -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| A web page or local program calls the route                                                        | The same Host, Origin, `Sec-Fetch-Site` and token checks as every route; JSON only; strict body of the text and two limits; a body can hold the longest statement                                            | Someone holding the token can read what the connected role can read (attacker 3 already can, through the Data tab)               |
| Writing through it                                                                                 | A read-only transaction on the server (`BEGIN READ ONLY`, `default_transaction_read_only`); the first word must be SELECT, WITH, VALUES, TABLE, EXPLAIN or SHOW                                              | A function the role may call that changes something outside the database (see below)                                             |
| Several statements in one text (`SELECT 1; COMMIT; DROP TABLE x`) ending the read-only transaction | The extended protocol (a named statement): the server refuses more than one command. Tested against a real PostgreSQL, and a mutation that removes it fails the test                                         | None known                                                                                                                       |
| `SET SESSION ...` changing a connection that a write transaction uses later                        | A connection opened for the one run and closed after it, never one of the pool; checked by a test that no `DataCanvas SQL` backend is left                                                                   | None known                                                                                                                       |
| `COPY ... TO PROGRAM`, `DO`, `CALL`: a read-only transaction does not stop them                    | Refused by the first-word check, in the adapter as well as the service (`not_allowed`)                                                                                                                       | A role that may run server programs from a function it calls, or read server files (`pg_read_file`): **the role is the control** |
| Taking the server down                                                                             | A statement timeout (30 s by default, 5 min at most), a lock timeout of 3 s, a cap of 1,000 rows (10,000 at most) read through a cursor, one statement at a time per connection, cancelling with the request | One statement can still use the server's CPU and memory for its timeout                                                          |
| Seeing what is masked in the Data tab                                                              | Not prevented: a query can alias or compute any column. Masking was never a control (it hides values from the screen)                                                                                        | Said in the view and the guide; the connected role's rights are the control                                                      |
| Text or values in logs and errors                                                                  | Nothing in the SQL path logs; a failure of the statement is returned to the person who typed it (the database's sentence and position); other failures use the fixed messages                                | The browser's and the server's memory                                                                                            |

A superuser, or a role that may execute server programs or read server files, can do more through a function call than a read-only transaction can prevent. The connection warns about such a role already (the role check), and the SQL view is where that warning matters most.

### 8b. Review of the SQL runner (1.6.0)

Before 1.6.0 the SQL runner was read by a second reviewer working only from the code, looking for any way a typed statement could write, change a session, run more than one statement, slip past the first-word check, exhaust memory or leave a backend running. It found two ways past the checks, both fixed, and some limits that are now written down.

| Finding                                                                                                                                                                                                   | Result                                                                                                                                                                                                                |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **High.** The first-word check ended a `--` comment at a line feed; PostgreSQL ends it at a carriage return too, so `--\rCOPY ... TO PROGRAM '...' /*\nSHOW x */` read as `SHOW` here and as `COPY` there | Fixed: white space is what PostgreSQL's lexer has, and a text with a carriage return, form feed or other control character is refused. Tested against a real server, and the same corpus in unit tests (decision 144) |
| **High, found while confirming a "speculative" item.** `EXPLAIN ANALYZE CREATE TABLE ... AS`, `CREATE MATERIALIZED VIEW` and `SELECT ... INTO` create the table inside a read-only transaction            | Fixed: `EXPLAIN` is allowed only for a plain query without the word `INTO`. Tested against a real server for each form                                                                                                |
| Memory: every row of a batch is held whole before cells are cut, and a result of huge rows could use all of it                                                                                            | Fixed for many rows: read 25 rows at a time and stop at 64 MB. **Accepted:** one single value of hundreds of megabytes is still read whole                                                                            |
| A cancel sent between two of our queries, or before the connection was up, was lost; an abort while connecting waited for the connect timeout                                                             | Fixed: the abort is heard from the start, a cancel is sent again every 250 ms until the run ends, and the backend is ended after a few tries                                                                          |
| A statement can call `set_config('statement_timeout', ...)` for the rest of its own transaction                                                                                                           | **Accepted:** the only later queries are two short ones of ours; the time limit of the statement itself was already running                                                                                           |
| CSV and TSV: a value starting with a line feed, white space before a formula character, or `\|`                                                                                                           | Fixed: defused with a leading apostrophe                                                                                                                                                                              |
| Functions that reach outside the database (`pg_read_file`, `dblink`, `COPY ... PROGRAM` for a privileged role), and a pooler making the backend id unreliable                                             | **Accepted and said in the view:** the role is the control. The SQL tab warns for a superuser or a role that may run programs or read server files                                                                    |

### 9. Migrations (1.7.0)

New capability: **text that is meant to be run elsewhere**, made from names and definitions that came from databases (`planMigration`, `buildExport`; decisions 147 to 151). It adds no route and no connection: the plan is a pure function of two structures, computed in the browser. DataCanvas never runs it.

| Attempt                                                                                            | Control                                                                                                                                                                       | Residual                                                        |
| -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| A hostile table, column, index or schema name that breaks out of the statement                     | Every name through `quoteIdentifier`, every literal through `quoteString`; round trips on a real PostgreSQL with hostile names for every kind of object                       | None known                                                      |
| A name or note with a line break that ends a `--` comment, or a carriage return that does too      | Text that is not SQL is cut to one line at every kind of break; held SQL is commented out line by line, cut at `\r`, `\n` and `\r\n`                                          | None known                                                      |
| A name that is a runner's command (`-- +goose Down`, `-- migrate:down`) inside a quoted identifier | The format is refused when such a line is not one of ours                                                                                                                     | The plain SQL formats are not affected                          |
| A hostile view or function whose text runs when the script runs                                    | Not prevented: running the script runs what it says. Every file says it holds definitions read from the databases and must be read first                                      | **The person reads the file.** The same holds for any `pg_dump` |
| A drop that loses data and is run by mistake                                                       | Flagged `destructive`, written commented out until confirmed per step, rollback marked `data_lost`; no statement uses `CASCADE`                                               | A confirmed drop is a drop                                      |
| A rename guessed wrong                                                                             | Renames are suggestions with the evidence, off until confirmed                                                                                                                | A person who confirms the wrong one                             |
| A migration that does less than the diff says                                                      | The comparison it is made from, and the list of what is not compared, are in every migration; the round-trip tests show the plan makes the starting database equal the target | What the structure reader does not record (said in the notes)   |

### 9b. Review of the migration generator (1.7.0)

Before 1.7.0 the generator (planner, renames, export, the tab) was read by a second reviewer working only from the code, looking for a statement that does more or less than the comparison says, text that breaks out of its place, and a format whose runner a name could command. It reproduced four high findings, six medium and five low, all fixed except where noted.

| Finding                                                                                                                                                                                                                                                         | Result                                                                                                                                                                                                                                  |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **High.** The comment-only step for a sequence that goes with its table (and the rollback text of a view whose definition was cut) wrote the object's name into a `--` comment unflattened: a sequence named with a line break ran `DROP SCHEMA` once confirmed | Fixed: every name in a comment goes through `flattenComment`; tests with line feeds and carriage returns in a sequence and a view name                                                                                                  |
| **High.** The runner guard allow-listed lines by text, so a name holding `-- +goose Down` or `-- migrate:down` (exactly our own marker) moved the Up and Down parts                                                                                             | Fixed: the text that is ours to write is checked, before the markers are added, for any line that looks like a command (any white space, any case, a line break between the dashes and the word); the format is refused if there is one |
| **High.** A collation whose name has a dot (`C.utf8`, `en_US.utf8`) was split at the dot and failed                                                                                                                                                             | Fixed: the schema and the name of a collation are recorded apart (snapshot format 3 gets `collationSchema`)                                                                                                                             |
| **High.** Renaming a column that owns a sequence left the sequence's owner stale: a bogus drop and, for a serial column, a new sequence restarting at 1 beside rows that exist                                                                                  | Fixed: a sequence follows its column in a rename, and a sequence that is gone and new with the same settings and owner is suggested as a rename (`ALTER SEQUENCE ... RENAME`), identity sequences included                              |
| Medium: steps did not record what they wait for (leaving out an added column kept its comment, constraint and index); a type change failed when the default could not be cast; a function read a column added in the same plan                                  | Fixed: steps wait for the column, schema, type, sequence or function they use; the default is dropped before such a type change and set after; a function that names an added column waits for the columns                              |

| Medium: tables that are partitioned, inherit, or are unlogged were made or dropped as plain tables without a warning                                                                                                                                            | Fixed: a warning for each such table made or dropped                                                                                                                                                                                    |
| Low: a placeholder in the header was not warned about; a policy, or a trigger naming a column, on a retyped column failed; a replaced view's rollback can fail; the Script tab differed from the exported file                                                  | Fixed: placeholder check over the whole file; such policies and triggers are made again; the replaced view's step says it can fail; the tab shows the text of the file                                                                  |
| Low: a held (unconfirmed) destructive step does not hold the steps that depend on it                                                                                                                                                                            | Fixed in 1.7.1: a step that depends on a held one, or is about the same object, is held too, with the reason                                                                                                                            |

### 10. Validation, the pre-flight, export and one cell (1.8.0)

New capability: **table data that leaves in a file** (export), **a read-write transaction on the read path** (validation) and **counts about the data** (the pre-flight). None writes a row; the JSON editor writes nothing itself (decisions 154, 156, 157, 158). All four routes are refused (403) unless data viewing is on for the connection, with the check before the database is touched, and share the per-connection read gate (export has its own: one at a time).

| Attempt                                                             | Control                                                                                                                                                                                                                                                                                                                                                                                          | Residual                                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A validation changes a row, advances a sequence, fires a trigger    | A temporary copy with no triggers, foreign keys, defaults or indexes; `SET TRANSACTION READ ONLY` before the first value; always rolled back, never committed; statements that change anything name only the copy (rule tests)                                                                                                                                                                   | A function in a CHECK with effects outside the database runs (the role is the control; the notes say so). An event trigger fires on the `CREATE TEMP TABLE` before the read-only switch and can write or advance a sequence (accepted; a note says one exists) |
| A hostile rule of the table writes a real table during a validation | The read-only switch: the write fails with SQLSTATE 25006 and is reported as "no effects" (tested against a function that inserts)                                                                                                                                                                                                                                                               | None known                                                                                                                                                                                                                                                     |
| A validation, pre-flight or export reads a hidden column            | Export leaves it out unless revealed and names it; the page reader's own checks apply (a hidden column is neither sorted nor filtered); the one-cell read refuses it; validation and the pre-flight return no value                                                                                                                                                                              | A column revealed on purpose, and a name that does not look sensitive but is                                                                                                                                                                                   |
| A value in a report, an error, a log or a file's notes              | Reports hold rules, names, counts and row numbers; errors are fixed text by SQLSTATE and never read the database's message; the notes of an export name conditions without their values (tests with a marker value in every field)                                                                                                                                                               | The file itself holds the rows you asked for                                                                                                                                                                                                                   |
| Injection through a name, a key value or a condition value          | Every name is compared with the catalog and quoted; every value is bound; a check of the pre-flight is a structure in a strict schema with no text field; the pre-flight and the migration path never run a CHECK constraint's text (a validation does evaluate the table's own CHECK constraints in its temporary copy)                                                                         | None known                                                                                                                                                                                                                                                     |
| A formula in an exported file                                       | The leading apostrophe of the SQL tab's export, written once in the core and pinned to it by a test                                                                                                                                                                                                                                                                                              | A spreadsheet that ignores it                                                                                                                                                                                                                                  |
| Taking the server down with an export                               | 100,000 rows, 64 MB, 10 minutes, a cursor read in batches sized by what they hold (at most 1,000 rows, about 4 million characters) whose speed follows the browser's, a write that waits a minute for a stopped reader is given up and the server ends an idle transaction after two minutes, one at a time per connection, a client that goes away ends the read and rolls the transaction back | One export can hold a connection for its limits                                                                                                                                                                                                                |
| A file that claims to be complete and is not                        | A cut is said at the end of the file (a `#` line, `_meta`, a last `_meta` line)                                                                                                                                                                                                                                                                                                                  | A file whose end was lost in transit (a stopped download)                                                                                                                                                                                                      |

### 10b. Review of validation and export (1.8.0)

Before 1.8.0 the validation, the pre-flight, the export and the one-cell read were read by a second reviewer (a fresh agent that was given the code and what it is for, not the author's conclusions), asked to reproduce each finding with a throwaway test and to change no source. It found no way to change real data, leave a temporary object or a lock, or put a value in a report or an HTTP error, and the data-access check came first in all four routes. It reproduced thirteen findings, none high; all are fixed and each has a test:

| Finding                                                                                                                                                                                           | Result                                                                                                                                                                                       |

### 14. Import modes, changes by filter, cell edits and text values (1.12.0)

New capability: **an import that updates rows by a key** (`upsert_rows`, `update_by_key`), **a change of every row a filter matches** (`update_matching`, `delete_matching`), **cells edited in the grid** (`edit_cells`) and **a cut text value read whole to be edited** (`getCell` for `text`, `varchar` and `citext`). They add no way to reach the database: they are operations of the same write service, behind the same three layers, preview, single-use id, plan guard and fixed errors (decisions 171 to 175). **They are not tools of the MCP server or commands of the CLI.** Two statement shapes are new: `ON CONFLICT (key) DO UPDATE | DO NOTHING` on the import batch, and the keyed `UPDATE ... FROM unnest` and `DELETE ... USING unnest` of 500 keys.

| Attempt                                                              | Control                                                                                                                                                                                                                                                                                                | Residual                                                                                                                                       |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| A filter becomes a destructive `WHERE`                               | It never does: the filter is used by the read of the preview to find keys; the write is the keyed batch; an empty filter is refused; at most 100,000 rows; any short batch rolls everything back (rule tests: no condition reaches a statement that writes)                                            | None known                                                                                                                                     |
| The held keys are a memory risk                                      | At most 100,000 keys and 8 million characters of key text (a key value at most 4,096 characters), held as arrays per batch, one such plan per connection, five minutes, dropped on lock, disconnect or data-access off                                                                                 | Up to about 17 MB for one plan; about 170 MB at ten connections (measured by the spike of the plan, section 13.4)                              |
| A change by filter hits rows other than the ones counted             | The keys are found at preview and applied as they are; a row deleted or re-keyed makes a batch short and rolls everything back; the typed count must equal the count the preview found, checked by the write service before the preview is used up                                                     | A row deleted and replaced by another with the same key between preview and apply is changed (the key is the identity; accepted, decision 172) |
| An overwrite is more than the person saw                             | The preview counts the rows that exist and says "N rows will be overwritten"; the change is destructive (tick in the dialog); each batch must report exactly the rows it carries                                                                                                                       | The tick is enforced by the browser, not by the server (see the last row)                                                                      |

### 14b. Review of 1.12.0

An independent reviewer (a separate agent with fresh eyes, 2026-11-27) read the whole write side of 1.12.0: the planners, the schemas, the preview store, the write service, the apply route, the browser logic and the tests of the security rules. **Reviewed and sound:** no SQL from a value, filter, key or column name (strict schemas, catalog names, bound values, the filter reaches only the read of the preview); no value in an error, a preview, the history or a skipped list; the preview store (single use, caps, no race between the count check and taking the plan, cleared on lock and on disconnect); the guards and the data-access check on every new operation; no MCP or CLI exposure; the counts and `expectRows` checks; length limits that agree between server, schema and browser.

**Findings, all fixed with a test that failed first:**

| Finding                                                                                                                                       | Severity      | Fix                                                                                                                         |
| --------------------------------------------------------------------------------------------------------------------------------------------- | ------------- | --------------------------------------------------------------------------------------------------------------------------- |
| An import by key (`update_by_key`, `upsert_rows`) on a key with a sensitive-looking name answered whether a key existed (an existence oracle) | Medium        | Such a key is refused before any read, with the same sentence whether or not the value exists; the dialog does not offer it |
| The cut-text editor changed CRLF line endings to LF                                                                                           | Low to medium | A value with `\r` is read-only, with the reason; a change that differs only by line endings is no change                    |
| Repeated keys under a case-insensitive collation were not found                                                                               | Low           | The check groups by the column's own collation                                                                              |
| `delete_matching` on a self-cascading table failed with the wrong message                                                                     | Low           | Refused at preview above one batch; a warning for one batch                                                                 |
| A table with child tables was accepted for changes by key                                                                                     | Low           | Refused with a fixed sentence (partitioned tables still work)                                                               |

**Accepted and written down:** the tick and the typed count of an import by key are enforced by the browser (the count of a change by filter is checked by the server); an upsert whose preview found no existing row needs no tick; a unique violation on apply can reveal that a written sensitive column collided with another row (as for an edit of one row); `listAll` validation can hold the page reads of a connection for up to 60 seconds; the rules of `tests/security.test.ts` are source patterns, and the integration tests carry the behaviour. **Not checked:** PostgreSQL 12 to 16 and 18, a role without `SELECT`, row-level security, and the memory of many concurrent large import previews.

## What happens on connection failure

The API returns a fixed message and a stable code (`unreachable`, `authentication_failed`, `ssl_error`, `timeout`...). The raw driver error, which can contain host names, user names or SQL, is never returned.

## What could leak through logs

Only error **codes** are logged for unexpected failures, never messages, bodies, URLs, cursors, rows or connection details. The invariant "the password never appears in any response" is tested on every connection route. The CLI prints the session-token link to the user's own terminal; that is by design, and the link is worthless after the process stops.

## Controls that are tested

Unit tests: `request-guard.test.ts` (Host, Origin, Sec-Fetch-Site, token, fail-closed), `error-response.test.ts` (guard inside every route), `web-server.test.ts` (loopback, token, telemetry off). Rule tests: `tests/security.test.ts` (every route guarded, no SQL endpoint, no CORS, no all-interfaces address; rows are read only behind the data-access check and are never logged; the data viewer keeps rows in component state only). Row tests: `rows-gate.test.ts`, the adapter tests against a real PostgreSQL (awkward names, every type, masking, row-level security, permissions, and that no error repeats a value), the end-to-end tests in `e2e/data-viewer.spec.ts`, a test that taking, exporting or importing a snapshot never calls `getRows`, and the rules for a sort and conditions (a strict schema at every level, no text built from them, no `LIKE`, nothing saved or kept in a store).

Write tests: the statement builders and the strict operation schemas (no `sql`, `where` or unknown key anywhere), the write service (each switch refused in order, single-use and expiring previews, one write at a time, history without values), the routes, rules that only the write service may reach the write capability and that no write path logs, and adapter tests against a real PostgreSQL (awkward names, conflicts, violations whose messages never contain the value, lock timeouts, refused drops), plus `e2e/writes.spec.ts`.

## Not covered

A review by a person or an outside party (the 1.5.2 review of the write path, the 1.6.0 review of the SQL runner and the 1.7.0 review of the migration generator were each done by a second model session), other operating systems and browsers, hardening against a same-user attacker.
